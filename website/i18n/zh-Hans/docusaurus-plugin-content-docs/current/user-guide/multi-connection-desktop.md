# 将 Desktop 连接到多个 Hermes 实例

将你拥有的每一个 Hermes 后端——本地运行时、LAN 或 VPS 上的远程网关、SSH
主机，以及 Hermes Cloud 实例——注册到一个桌面应用中，并同时使用它们上面
的智能体。连接是持久化的：每个已注册的网关会按需拨号连接自己的后端和
WebSocket，当你在查看另一个网关时，后台智能体仍会持续流式传输。

这是桌面端的补充内容，与
[同时运行多个网关](./multi-profile-gateways.md)相对：那一页讲的是在一台机器上
托管多个网关；这一页讲的是一个桌面应用与多台机器通信。

## 在哪里找到它

一切都在统一的 **Settings → Gateways** 页面上（较旧的版本有分开的
**Gateway** 和 **Connections** 页面；旧版 Connections 的深层链接会重定向到
那里）。有三条途径可以到达该页面：

- **Settings → Gateways** — 页面本身（**Cmd/Ctrl+,**，然后在设置导航中点击
  **Gateways**）。连接注册表是该页面的一个分区，位于机器级连接模式控件
  下方。
- **侧边栏的配置揽** — 栏最右端的插头按钮
  （工具提示：**"Connect another Hermes gateway…"**）会深层链接直接跳到
  Gateways 页面。即使你还没有创建第二个配置档或第二个连接，它也始终可见。
- **命令面板** — **Cmd/Ctrl+K**，然后输入 *Gateways*（也能匹配
  *connections*、*add gateway*、*remote*、*ssh*、*instances*）。

## 网关注册表

**Settings → Gateways** 中的 **已注册的网关** 部分管理着一份具名的
Hermes 网关列表。它的介绍说得明白：*"管理此设备以及它能通过远程、SSH 或
Cloud 连接到达的每一个 Hermes 网关。"*
每个条目都是一个 *连接*：

| 类型 | 它是什么 | 认证 |
|---|---|---|
| **Local** | "此应用管理的 Hermes 运行时。" | 自动 |
| **Remote gateway** | "可通过 HTTP(S) 到达的 Hermes 网关——LAN、Tailscale 或互联网。" | 会话令牌或 OAuth |
| **SSH** | "通过 SSH 到达的 Hermes 安装。" 应用会为你打开隧道并启动仪表盘 | SSH 密钥 + 采用的令牌 |
| **Hermes Cloud** | "通过你的 Hermes Cloud 账户发现的自托管实例。" | 门户登录 |

值得了解的规则：

- **每个连接都需要唯一的设备名称**（"Homelab"、"Work laptop"）。
  该名称会出现在该实例出现的一切地方——花名册徽章、句柄、
  更新结果。唯一性不区分大小写，因此 `Homelab` 和 `homelab`
  不能共存。
- **local** 条目由应用管理（它带有一个 **App-managed** 药丸标记），
  并且不能被移除。移除其他任何连接都会拆除其活跃的
  后端和隧道；实例本身不受影响。
- 总有一个连接是 **Primary**（其行上有药丸标记）：它是注册表中那些
  未指定网关的多网关调用的回退项。
  **Make primary** 不会切换当前的 Sessions 工作区；移除
  主连接会回退到本地条目。
- **Startup, return to Sessions on the last-used gateway 在完整应用重启后，控制在哪个网关上打开 Sessions。它默认关闭，因此
  Sessions 会在
  **Primary** 上打开。开启它以恢复最近一次成功连接的网关。失败的
  切换永远不会被记住，而已移除或不可用的已保存网关
  会回退到 Primary。
- **Test** 会探测连接自身的 HTTP *和* WebSocket 两段，因此通过
  （*"Reachable"* 提示）意味着聊天真的能工作——而不仅仅是主机能
  被 ping 通。
- **重复项会在保存时被拒绝**：**local**
  条目永远只有一个；**remote** 和 **cloud** 条目会按规范化后的
  URL 去重（去除首尾空白、去除尾部斜杠、转为小写——而且是跨两种
  类型去重，因此一个 cloud 条目和一个 remote 条目不能指向同一个 URL）；
  **SSH** 条目会按规范化后的 `user@host:port` 加上
  远程配置档去重。
- Cloud 条目通常来自 Gateways 页面顶部的 Hermes Cloud 登录/发现流程
  ——添加连接编辑器中的 **Hermes Cloud** 类型会把你引导
  到那里。

从 **Sessions** 侧边栏切换网关。配置档、聊天、消息传递和
定时任务仍限定在该网关范围内；应用管理的窗口后端仍由上方
的连接模式控件选择。**Primary** 是注册表回退项，
不会切换当前工作区。

## 组织会话分组

在会话侧边栏的视图菜单中，查看所有配置档时选择 **Gateway & profile**。每个网关都有自己的可折叠区段，其中包含配置档子区段及其会话。两个带有 `default` 配置档的网关保持相互独立。网关标题以已保存的连接名称开头；配置档标题显示配置档名称。

使用网关或配置档区段的菜单可以 **Rename group**（重命名分组）、**Reset name**（重置名称）、**Move up**（上移）或 **Move down**（下移）。重命名只会更改侧边栏标签，不会更改网关或配置档。网关作为完整区段重新排序，配置档在其所属网关内重新排序。拖动区段的前导图标可对其重新排序，或将焦点置于该拖动手柄上，按 Space、方向键，再按 Space 进行放置。名称、顺序和折叠状态会在此桌面上被记住。折叠网关会保留其各个配置档各自的折叠状态。每个配置档的“新建会话”操作会在其所属网关上以该配置档为目标。

当门户发现处于未登录状态时，Hermes Cloud 面板还会列出 **Saved Cloud gateways**（已保存的 Cloud 网关）。**Use gateway**（使用网关）会选择现有的已保存连接而不更改默认网关；**Active in this window**（此窗口中活动）标识当前使用的连接。添加新实例时使用其友好的 Cloud 名称，而现有的自定义连接名称会被保留。已保存的连接仍需要有效的网关认证；请通过已注册连接控件进行登录管理。

## 逐步添加连接

1. 打开 **Settings → Gateways**，滚动至关连接注册表（或点击配置档栏中的插头图标）。
2. 点击 **Add connection**（添加连接）。
3. 选择类型：**Local**、**Hermes Cloud**、**Remote gateway** 或 **SSH**。
   （当应用管理的本地条目存在时——几乎总是如此——**Local** 会被禁用；**Hermes Cloud** 会将你引导至上述的 Cloud 登录/发现流程。）
4. 填写字段：
   - **Name** — 必填，唯一；即此实例在随处出现时显示的“设备名称”（占位符：`Homelab`）。最多 64 个字符。
   - *仅限 Remote gateway：*
     - **Gateway URL** — 正在运行的 `hermes serve` 后端的基 URL，
       例如 `http://homelab.lan:9119`。支持反向代理路径前缀。
     - **Authentication** — 选择 **Session token** 或 **OAuth**：
       - **Session token** — 粘贴来自远程网关的仪表板会话令牌。编辑时，*"Leave blank to keep the saved token."*（留空则保留已保存的令牌。）
       - **OAuth** — 通过 Nous Portal 浏览器流程登录；无需粘贴令牌。
   - *仅限 SSH：*
     - **SSH host** — 一个 `user@host:22` 形式的复合字段（user 和 port 可选）。将使用你的 SSH 密钥；应用会通过隧道获取仪表板令牌。
5. 点击 **Save connection**（或 **Cancel**）。
6. 点击新行上的 **Test**，等待显示 *"Reachable"*（可达）。

之后可用铅笔按钮编辑任何非本地条目，或用垃圾桶按钮将其移除——移除时会要求确认，并提醒你 *"The instance itself is not touched — you can add it again any time."*（实例本身不会被改动——你可以随时重新添加它。）

:::info 远程后端是正在运行的 `hermes serve` 进程
除非后端确实已在另一台机器上启动且可达，否则这里的一切都无法工作。桌面应用会附连到它；它不会替你启动它（SSH 连接除外，此时应用会按需通过隧道启动仪表板）。关于后端侧的设置——认证服务商、绑定到非回环地址以及 Tailscale 指导，请参阅
[Connecting to a remote backend](./desktop.md#connecting-to-a-remote-backend)。
:::

### 从单连接设置迁移

首次启动支持注册表的构建版本时，会自动导入你现有的设置：全局连接模式以及 Settings → Gateway 中任何旧的按配置档覆盖项都会成为具名注册表条目（按 URL/主机去重）。（较新的构建版本不再在 Gateways 设置页面中提供按配置档覆盖项——网关连接是机器级别的，配置档则从你连接的网关中发现。）
旧的设置文件保持不动，因此同一台机器上的旧版本构建仍可继续工作。如果迁移后的名称发生冲突，会被加上后缀（`Homelab 2`）。

## 跨网关的智能体

每个已注册连接上的每个 [配置档](./profiles.md) 都是一个 *智能体*。
联合名册正是多网关界面（以及内置的 [Bot 模式](./bot-mode.md) 名册）所渲染的内容：

- 当同一个配置档名称存在于多个网关上时，句柄会消歧为 **`@name-device`** —— 你在 Homelab 上的 `research` 会显示为 `@research-homelab`，而在所有网关上唯一的配置档则保留其裸名称。
- 枚举是急切执行的，但套接字是惰性的：应用通过 REST 列出智能体，无需拨通每个网关的 WebSocket。无法访问的网关会按行报告，而不是破坏整个名册；SSH 连接保持按需连接，直到你首次在其上打开某个智能体（不会出现意外的隧道）。
- 打开一个智能体时，会拨通 **它自己的网关** —— 聊天、会话和记忆都位于拥有该配置档的那台机器上，就如同你直接使用那个实例一样。

每个 `(connection, profile)` 对都会获得自己的后端和套接字，并与本地按配置档划分的后端以相同的空闲回收策略进行池化 —— 后台智能体在你查看另一个网关时仍会继续流式输出。

批准按钮会路由回会话所属的后端，而不是当前选中的任意配置档。对于本地的次要配置档，即使缓存的会话绑定缺失，Desktop 也可以使用投递该请求的套接字。已保存的会话归属关系仍然优先，删除或重命名该本地配置档会清除这条临时路由，而不是重连一个已过时的后端。

### 切换与作用域

侧边栏底部遵循一个层级：**网关 → 配置档 → 会话**。
网关是机器或托管后端；配置档是宿于某个网关之上的、相互隔离的 Hermes 智能体。

- 只注册了一个网关时，不会添加网关控件。纯本地的 Desktop 保持与之前相同的配置档竖栏和键盘操作流程。
- 有多个网关时，侧边栏显示一个具名的网关选择器。其设备、云端、网络或终端图标标明了连接类型；配置档头像在分隔线之后仍是独立的控件。同一个选择器可以从两个网关扩展到更大的机群，而不会把后端变成类似配置档的图标符号，也不会把配置档操作挤挤出竖栏。
- 选择一个网关会恢复该处最后使用的配置档。主页面胶囊会恢复到其默认配置档，图层胶囊会显示 **此网关上的所有配置档**。**Cmd/Ctrl+1–9** 会继续在活动网关内切换配置档。
- 有多个网关时，配置档竖栏是一个 **机群竖栏**：每个已注册网关的配置档都排在同一条细条上，每组以该网关的类型图标（设备、网络、终端、云端）作为组头 —— 与网关选择器使用的图标相同。活动网关的方块看起来与单网关 Desktop 上的完全一致；其他网关的方块处于变暗（“静置”）状态。悬停在静置状态的方块上会显示其所在机器名称（`omer · 此设备`），因此不同机器上两个同名配置档永远不会读数相同。
- 点击一个静置方块与操作网关选择器会执行相同的切换，落到精确的 `(gateway, profile)`：在目标被拨通时该方块会旋转，前一个网关保持着色直到目标应答，而目标失联会使点击以一条消息失败，而不是让窗口处于半切换状态。无论哪个网关处于活动状态，各组都保持注册顺序，因此方块绝不会在点击它的指针下方移动。右键点击静置方块会提供 **切换到**、**颜色**、**重命名**、**编辑 SOUL.md** 和 **删除**，全部在方块自己所属的网关上执行；删除确认信息会注明机器名称。
- 上次枚举未能访问到的网关会保留其方块，并以其图标上的琥珀色圆点标记 —— 一个休眠的机器仍然是你的。同一个后端的两次注册会折叠成一个组。整个机群超过十三个方块时，细条会浓缩为一个按网关分节的菜单。
- 只有在开启了 **设置 → 网关 → 启动时，在最后使用的网关上返回会话页** 时，选中的网关才会在退出并重新启动后保留。该首选项和网关 id 存放在应用的用户数据注册表中，因此替换或更新应用包不会重置它们。
- 活动网关上的配置档超过十三个时，其头像条会浓缩为一个具名的配置档选择器。因此，大型的网关集合与配置档集合可以并存，而不会改变 **网关 → 配置档 → 会话** 模型。
- 即使远程连接是主连接，**此设备** 仍然是一等网关。它可以在远程中断期间保持本地会话可用，但应用不会将其称为“离线模式”：所选模型或工具可能仍需要互联网访问。
- 会话列表、消息渠道、定时任务、设置、文件和记忆都限定于活动的 `(gateway, profile)`。从 Telegram 网关切换到 Signal 网关不会让前一网关的渠道组或会话残留在侧边栏中。
- 仅仅显示切换器只会读取 Electron 的本地连接注册表。远程网关只在被选中时才会打开；不存在定期的机群轮询。
- 悬停在某个智能体上会预热其后端，从而使切换无需承担冷启动开销。
- **能力** 页面（技能 / 工具 / MCP）具有匹配的作用域：其 **正在配置** 选择器列出联合名册中的每个 `(profile, device)` 智能体，选取其中一个会读写 **那台机器上** 的技能、工具集和 MCP 服务器，而不会切换会话工作区。Hub 安装、环境变量密钥和 MCP 设置全部落到所选智能体的后端上。MCP 标签页的 *热重载到实时会话* 按钮只对窗口所连接网关上的智能体显示；其他机器上的编辑会在它们的下一个会话中生效。

在 **设置 → 网关** 中添加、测试、重命名或移除网关。配置档操作旁边的插头按钮是通往该单一管理主页的快捷方式，而不是第二条添加流程。

### 会话与机器人模式

会话有意一次只显示一个活动网关：这样可以让文件、工具、渠道、定时任务和会话历史保持在同一个易于理解的执行上下文中。多配置档栏只拓宽了*选择器*——每次点击后工作区仍然只存在于一个 `(gateway, profile)` 上。机器人模式服务于不同的任务，可能会按网关分组呈现联合名单，这样用户可以从同一界面打开 NAS 上的一个智能体和 VPS 上的另一个。打开机器人仍然会激活其确切的 `(gateway, profile)` 路由。

直接提及机器人和委派默认仍然局限于本网关。跨越后端边界会改变文件系统、凭据、工具和信任上下文，因此跨网关执行应当是通过显式桥接实现，而不是共享同一个 Desktop 窗口所导致的意外副作用。

## 一次性更新所有实例

**Settings → Gateways → Update all instances**（在注册了多个连接后才会显示）会并行向每个符合条件的连接分发 `hermes update`：

- **本地**连接通过应用自身的更新流水线更新（与 Settings → Updates 相同流程）。
- **远程和 SSH** 连接被通知通过各自的后端自行更新——更新在*那台*机器上运行。
- **Hermes Cloud** 实例会被跳过，并附有*“由 Hermes Cloud 管理”*的说明：平台管理其版本。

每个实例独立报告，因此一个不可达的节点永远不会卡住整批。以外部方式管理更新的后端（Docker、Nix）会按行礼貌地用自己的消息拒绝。

不过你很少需要用到 Settings 按钮：一旦存在多个更新目标，应用的常规更新入口（About 面板上的 **Update now**、⌘K 的 **Update Hermes**、更新就绪提示）会自动执行相同的扇出流程——先更新活动后端，然后更新其他所有符合条件的网关，最后更新桌面应用本身。请参阅桌面指南中的[更新](./desktop.md#updating)。

## 安全说明

- **令牌存放位置。** 远程网关会话令牌（以及按网关基础 URL 键控的原生登录 OAuth 令牌）作为仅属主可访问（0600）的文件，存储在应用的用户数据目录中，位于 Electron 主进程内；渲染进程和插件永远看不到令牌字节。
- **可选的钥匙串加密。** 默认情况下，令牌**不会**经过操作系统钥匙串——尤其是在 macOS 上，Electron 的 `safeStorage` 会在登录钥匙串中放置一个按应用隔离的密钥，钥匙串被锁定或损坏会导致每次启动时弹出密码提示。如果你希望在文件权限之上再加一层静态加密，请打开 **Settings → Gateway → "Encrypt saved secrets with the OS keychain"**(使用操作系统钥匙串加密已保存的密钥)；现有已存储的密钥会被原地重新加密（macOS 上用 Keychain，Windows 上用 DPAPI，Linux 上用会话钥匙环后端）。将其重新关闭则再次解密。
- **注册表文件**（应用用户数据目录下的 `connections.json`）保存标签、URL 和主机——密钥只会出现在加密信封内部。
- 插件 SDK 的 `host.connections()` 有意只返回标签、种类和主 id——绝不返回令牌内容。

## 面向插件开发者

Desktop [插件 SDK](../developer-guide/desktop-plugin-sdk.md) 直接暴露多网关接口：

- `host.connections()` — 已注册的连接列表（标签、种类、主连接；绝不含令牌字节）。
- `host.agents()` — 联合名单：每个 `(gateway, profile)` 一行，包含预计算的 `@name-device` 句柄。
- `host.ensureAgent(connectionId, profile)` — 激活某个智能体的网关，以便后续 `host.request` 调用命中其后端。
- `host.warmAgent(connectionId, profile)` — 即发即忘的套接字预热（悬停意图）。

这四个都做了特性检测：在较旧的 Desktop 版本上它们不存在，插件应回退到单网关的 `profiles.list` 流程。机器人模式的多网关名单是参考消费方。

## 故障排除

- **"Connection test failed"(连接测试失败)** — 从本机无法通过该 URL 访问后端。请检查 `hermes serve` 是否在远程主机上运行、端口是否开放，以及（对于令牌认证）令牌是否为最新。修复后重新运行 **Test**。
- **某个智能体显示出来但无法打开** — 对其连接运行 **Test**。HTTP 通过但 WebSocket leg 失败，通常意味着有代理、防火墙或网关认证/来源防护阻止了 `/api/ws`。
- **名单中缺少某个远程网关** — 其后端宕机或不可达；名单会将其列在网关下并附上错误。SSH 连接在首次使用前显示*按需连接*——这是设计如此，并非故障。
- **"Update Hermes Desktop to chat with agents on other connections"** — 该应用早于多连接技术栈；请更新桌面应用自身。
- **设备名称重复** — 不可能；名称在保存时强制唯一。如果迁移的名称发生冲突，会被加上后缀（`Homelab 2`）。
- **"Could not save the connection"** — 最常见原因是缺少 **Name**、名称已被占用，或 **Gateway URL** / **SSH host** 格式错误；错误消息会指明具体违反项。
