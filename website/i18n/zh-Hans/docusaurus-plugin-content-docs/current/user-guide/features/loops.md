# 循环任务（`/loop`）

`/loop` 会**在你当前的会话内**按固定节奏重复运行同一个提示词（或斜杠命令）。每次唤醒都是一次真实的智能体回合：Hermes 读取当前最新状态 — 最新的 CI 结果、最新的队列深度、此刻的文件内容 — 执行任务、回报结果，然后静默等待下一个周期。

这是 Hermes 对 **Claude Code `/loop`** 的实现（其 `/proactive` 别名在这里同样可用）。[`/goal`](./goals.md) 由判定驱动 — "持续工作直到目标达成"；而 `/loop` 由定时器驱动："每隔 N 分钟（或在合理的时机）重复执行这项操作，直到某个条件触发停止。"

## 适用场景

- **轮询外部状态。** "盯住这次部署 / CI 运行 / 队列，有变化就告诉我。" 这是最典型的用法。
- **迭代至通过。** "运行测试，修复失败项，反复执行直到全部通过。"
- **工作期间的监控。** 在同一段对话里你处理其他事情时，持续关注错误率或长时间任务的进度。
- **周期性维护。** 在长时间的会话中每隔 N 分钟重新运行一次 lint 检查或状态摘要。

当任务需要**无人值守**运行 — 通宵、按真实日程、在终端重启后仍继续 — 应改用[定时任务](./cron.md)。`/loop` 存在于会话之内；cron 存在于所有会话之外。而当任务是一个有明确完成定义的单次目标时，[`/goal`](./goals.md) 通常更合适。

## 快速上手

```
/loop 5m check the deploy status and tell me if it's live yet
```

你会看到：

1. **循环已接受** — `↻ Loop set (every 5m): check the deploy status…`
2. **首次唤醒立即触发** — 在下一次空闲轮询时（网关：下一次 15 秒的监听器扫描），Hermes 注入唤醒并针对当前状态运行一个常规回合。
3. **重复执行** — 此后每 5 分钟一次，直到某个停止条件触发或你主动停止。

循环运行斜杠命令同样简单：

```
/loop 10m /recap
```

## 两种节奏模式

**固定间隔 — 由你设置时钟。** 给定一个间隔（`30s`、`5m`、`2h`、`1h30m`），循环按该时间表触发。当你监控的对象按自身的节奏变化时使用它：

```
/loop 2m poll the build at ci.example.com/job/42 and ping me the moment it finishes
```

**自适应节奏 — 由 Hermes 设置时钟。** 省略间隔后，循环会自行调整节奏：从下限开始（默认 1 分钟），当智能体的回复不再变化时，它会指数级退避 — 2 分钟、4 分钟、8 分钟，直至上限（默认 15 分钟）。一旦某次回复与上一次不同，节奏立即回落到下限。变更检测是本地摘要对比（忽略时间戳），因此空闲等待不会产生额外开销：

```
/loop keep an eye on the migration and summarize progress
```

经验法则：**当外部时钟驱动工作时使用固定间隔；当工作驱动节奏时使用自适应节奏。**

## 停止条件

以下任一条件触发时，循环结束：

| 条件 | 说明 |
|---|---|
| 智能体判断已完成 | 唤醒提示词会教导智能体在任务完成或已无意义时，在回复的末尾单独一行输出 `LOOP_COMPLETE`。 |
| 运行次数上限 | `--times N` — N 次唤醒后停止。 |
| 基于证据的条件 | `--until <条件>` — 每次唤醒后，驱动 `/goal` 的同一辅助判定模型会根据你的条件检查回复。若判定模型认为条件无法实现，循环会**暂停**并说明原因，而不是继续触发直至每周期预算（失败放行：判定模型异常不会卡死循环）。 |
| 你 | `/loop stop`（或用 `/loop pause` 保留循环）。 |
| 兜底预算 | `loops.max_ticks`（默认 100）会暂停循环，防止无人值守的会话无限消耗 tokens。`0` = 不限制。 |

示例：

```
/loop 2m poll CI --times 30
/loop 5m watch the queue --until queue depth reaches zero
```

## 命令

| 命令 | 作用 |
|---|---|
| `/loop [interval] <prompt> [--times N] [--until <cond>]` | 为该会话启动（或替换）循环。首次唤醒立即触发；后续按节奏执行。 |
| `/loop` 或 `/loop status` | 显示节奏、已触发次数以及距离下次唤醒的时间。 |
| `/loop pause` | 停止触发但不丢失循环。 |
| `/loop resume` | 恢复执行。 |
| `/loop stop` | 结束循环。 |
| `/proactive …` | `/loop` 的别名（与 Claude Code 对齐）。 |

适用于 CLI、TUI（`hermes --tui`）、Web 仪表盘聊天、桌面应用以及所有网关平台（Telegram、Discord、Slack、WhatsApp……）。在消息平台上，网关即使在你两次消息之间也会触发唤醒 — 循环属于该聊天的会话，其结果以普通回复的形式投递。

## 与 `/goal` 混用

两个功能都会在空闲边界注入合成回合，因此遵循一条规则：**活跃的目标掌控会话。** 当 `/goal` 正在主动驱动（判定模型输出"继续"）时，循环唤醒会退让。一旦目标完成、暂停或因等待屏障（`/goal wait`，或判定模型自动给出 WAIT 判定）停驻，循环便立即利用空闲时间恢复执行。停驻的目标加 `/loop` 是天然的组合：目标等待重要的大型异步任务，而循环则在其他事项上保持心跳。

真实用户消息的优先级始终高于两者 — 唤醒仅在会话空闲且没有你的消息排队时才触发。

## 行为细节

- **唤醒是一次普通的 user 角色回合。** 不修改系统提示词，不切换工具集 — 提示缓存保持不变。
- **能挺过 `/resume` 和上下文压缩。** 循环状态按会话持久化，并能跨越上下文压缩边界迁移，与 `/goal` 相同。
- **每个会话一个循环。** 设置新的 `/loop` 会替换旧的。要运行多个循环，请开启多个会话（或用 cron 批量管理各种时间表）。
- **中断唤醒回合（Ctrl+C）会暂停循环** — 可用 `/loop resume` 恢复，因此取消就是真的取消。
- **Token 开销与节奏成正比。** 每个周期都是一次完整的智能体回合。让间隔匹配状态实际变化的频率；空闲等待时优先使用自适应节奏。

## 配置

```yaml
# ~/.hermes/config.yaml
loops:
  min_interval_seconds: 30       # 固定间隔的下限
  max_ticks: 100                 # 兜底预算（0 = 不限制）
  self_paced_floor_seconds: 60   # 自适应节奏的起始值
  self_paced_ceiling_seconds: 900  # 自适应节奏的最大退避值
```

`--until` 的判定通过 `goal_judge` 辅助任务路由，因此 `auxiliary.goal_judge.*` 的路由覆盖项（服务商、模型）同样适用于循环条件。

## `/loop` vs `/goal` vs 定时任务

| | `/loop` | `/goal` | 定时任务 |
|---|---|---|---|
| **触发方式** | 定时器（或自适应节奏） | 每回合后的判定模型结论 | 计划日程，独立于任何会话 |
| **存在于** | 你当前的会话 | 你当前的会话 | 每次运行各自的会话 |
| **结束于** | 停止条件 / 上限 / 你 | 目标达成 / 预算 / 你 | 你移除该任务 |
| **最适合** | 轮询、监控、周期性重跑 | 单一目标，迭代直到完成 | 无人值守、长周期计划 |
