# 循环任务（`/loop`）

`/loop` 会**在你当前会话中**按固定节奏重复运行一个提示词（或斜杠命令）。每次唤醒都是一次真实的智能体回合：Hermes 全新读取当前状态 —— 最新的 CI 结果、最新的队列深度、文件此刻的样子 —— 完成工作、回报结果，然后安静下来直到下一个心跳。

这是 Hermes 对 **Claude Code 的 `/loop`** 的实现（其别名 `/proactive` 在这里也同样可用）。[`/goal`](./goals.md) 由判定驱动 ——“持续工作直到目标达成”；而 `/loop` 由定时器驱动：“每隔 N 分钟（或在合适的时候）再做一次，直到某个条件叫停”。

## 什么时候用

- **轮询外部状态。**“盯着部署 / CI 运行 / 队列，有变化就告诉我。”最典型的用例。
- **迭代到全绿。**“运行测试，修复失败项，重复直到通过。”
- **工作期间监控。** 在同一个对话里做别的事时，留意错误率或长任务的进度。
- **周期性收拾工作。** 在长时间会话中每隔 N 分钟重跑一次 lint 或生成状态摘要。

当工作应当**无人值守**运行 —— 过夜、按真实日程、在终端重启后仍存活 —— 请改用[定时任务](./cron.md）。`/loop` 活在会话内部；cron 活在所有会话之外。而如果任务是一个明确的目标且有完成定义，[`/goal`](./goals.md) 通常是更合适的选择。

## 快速上手

```
/loop 5m check the deploy status and tell me if it's live yet
```

你会看到：

1. **循环已接受** —— `↻ Loop set (every 5m): check the deploy status…`
2. **第一次唤醒立即触发** —— 在下一个空闲轮询（网关：下一次 15s watcher 扫描）时，Hermes 注入唤醒并针对当前状态运行一个正常回合。
3. **重复** —— 此后每 5 分钟一次，直到某个停止条件触发或你手动停止。

循环一个斜杠命令同样简单：

```
/loop 10m /recap
```

## 两种节奏模式

**固定间隔 —— 你定时钟。** 给出一个间隔（`30s`、`5m`、`2h`、`1h30m`），循环按该日程触发。当你监视的事物按自己的时间线变化时使用它：

```
/loop 2m poll the build at ci.example.com/job/42 and ping me the moment it finishes
```

**自我调速 —— Hermes 定时钟。** 省略间隔，循环自行调节节奏：从下限（默认 1 分钟）开始，当智能体的回复不再变化时，它会指数退避 —— 2m、4m、8m，直到上限（默认 15 分钟）。一旦某次回复与上一次不同，节奏立即弹回下限。变化检测是本地摘要比对（忽略时间戳），因此空闲等待不会额外增加成本：

```
/loop keep an eye on the migration and summarize progress
```

经验法则：**外部时钟驱动工作时用固定间隔；工作驱动节奏时用自我调速。**

## 停止条件

只要以下任一条件触发，循环就结束：

| 条件 | 方式 |
|---|---|
| 智能体决定完成 | 唤醒提示词教会智能体在任务完成或不再必要时，在回复末尾单独一行以 `LOOP_COMPLETE` 结束。 |
| 运行次数上限 | `--times N` —— 运行 N 次唤醒后停止。 |
| 基于证据的条件 | `--until <condition>` —— 每次唤醒后，与支持 `/goal` 的同一辅助判定器会比对你的条件与回复。如果判定器裁定该条件无法达成，循环会**暂停**并给出原因，而不会持续触发到 tick 预算耗尽（fail-open：判定器坏掉绝不会卡死循环）。 |
| 你 | `/loop stop`（或 `/loop pause` 将其保留）。 |
| 兜底预算 | `loops.max_ticks`（默认 100）会暂停循环，以免无人值守会话无限燃烧 token。`0` = 无限制。 |

示例：

```
/loop 2m poll CI --times 30
/loop 5m watch the queue --until queue depth reaches zero
```

## 命令

| 命令 | 作用 |
|---|---|
| `/loop [interval] <prompt> [--times N] [--until <cond>]` | 启动（或替换）该会话的循环。第一次唤醒立即触发；此后按节奏跟进。 |
| `/loop` 或 `/loop status` | 显示节奏、已触发次数，以及距离下次唤醒的时间。 |
| `/loop pause` | 停止触发但保留循环。 |
| `/loop resume` | 恢复运行。 |
| `/loop stop` | 结束循环。 |
| `/proactive …` | `/loop` 的别名（对齐 Claude Code）。 |

该功能适用于 CLI、TUI（`hermes --tui`）、Web 仪表盘聊天、桌面应用以及所有网关平台（Telegram、Discord、Slack、WhatsApp……）。在消息平台上，即使在你的消息之间，网关也会触发唤醒 —— 循环属于聊天的会话，其结果作为普通回复送达。

## 与 `/goal` 混用

这两个功能都会在空闲边界注入合成回合，因此遵循一条规则：**一个活跃的 goal 拥有该会话。** 当 `/goal` 正在主动驱动（判定器说“继续”）时，循环唤醒会推迟。goal 一旦完成、暂停或在等待屏障上停滞（`/goal wait`，或判定器自动的 WAIT 裁定），循环就利用空闲时间恢复。久等的挂起 goal 加上一个 `/loop` 是自然组合：goal 等待大的异步事项，而循环持续对其他事物心跳检测。

真实用户消息总是优先于二者 —— 唤醒只在会话空闲且你没有任何排队的消息时触发。

## 行为细节

- **一次唤醒是普通的 user-role 回合。** 不修改系统提示词、不切换工具集 —— prompt 缓存保持完好。
- **在 `/resume` 和压缩后仍存活。** 循环状态按会话持久化，并跨上下文压缩边界迁移，与 `/goal` 相同。
- **每个会话一个循环。** 设置新的 `/loop` 会替换旧的。需要多个循环就运行多个会话（或用 cron 做一整套日程）。
- **中断一次唤醒回合（Ctrl+C）会暂停循环** —— 可用 `/loop resume` 恢复，因此取消就是真的取消。
- **Token 成本随节奏缩放。** 每一次 tick 都是一次完整的智能体回合。调间隔匹配状态实际变化的频率；空闲等待优先用自我调速。

## 配置

```yaml
# ~/.hermes/config.yaml
loops:
  min_interval_seconds: 30       # 固定间隔的下限
  max_ticks: 100                 # 兜底预算（0 = 无限制）
  self_paced_floor_seconds: 60   # 自我调速的起始节奏
  self_paced_ceiling_seconds: 900  # 自我调速的最大退避
```

`--until` 判定器通过 `goal_judge` 辅助任务路由，因此 `auxiliary.goal_judge.*` 的路由覆盖（服务商、模型）也适用于循环条件。

## `/loop` vs `/goal` vs cron

| | `/loop` | `/goal` | cron |
|---|---|---|---|
| **触发方式** | 定时器（或自我调速） | 每回合后的判定器裁定 | 日程，在任何会话之外 |
| **所居之处** | 你当前的会话 | 你当前的会话 | 每次运行各用自己的会话 |
| **结束条件** | 停止条件 / 上限 / 你 | 目标达成 / 预算 / 你 | 你移除该任务 |
| **最适合** | 轮询、监控、周期性重跑 | 单一目标，迭代至完成 | 无人值守、长周期日程 |
