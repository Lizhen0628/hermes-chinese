# 本地模型

Hermes 可以完全在你自己的机器上运行开放模型。它会下载并管理推理引擎（llama.cpp），为你的硬件挑选每个模型的正确构建版本，并负责内存管理，因此你永远无需配置上下文大小、GPU 层数或量化。你只需挑选一个模型，剩下的交给 Hermes。

不会有任何数据离开你的电脑：无需账户、无需 API key，模型下载完成后也无需网络访问。

## 快速开始

1. 打开 **Settings → Providers → Local Models**（或在引导流程中选择 **Run models locally**）。
2. 点击 **Install runtime**。Hermes 会为你的硬件下载官方 llama.cpp 构建版本（几百 MB），验证它，并保持其更新。
3. 从目录中挑选一个模型并点击 **Download**。
4. 点击 **Use**。新对话现在就在本地模型上运行了。

整个流程就是这样。服务器随 Hermes 一起启动和停止，应用重启后依然存活，切回云端服务商只需在模型选择器中点一下即可。

## Hermes 如何决定下载什么

在你下载任何内容之前，目录中的每个模型都会针对 **你的机器** 评估。每一行都显示：

- **内存适配度** — 绿色（*适配你的 GPU*：完全在 GPU 内存中运行）、琥珀色（*使用系统内存*：可以运行，但较慢），或红色（*对本机过大*）。
- **上下文** — 模型初始的窗口大小以及它可增长到的最大值。
- 为你的硬件所选构建版本的下载大小。

模型以多种质量等级（量化）发布。Hermes 会选择能够在你的 GPU 上完整运行的最高质量构建版本；内存较少的机器会获得同一模型的更紧凑构建版本，并带有相同的保证。低于 4-bit 时质量损失过于严重，因此 Hermes 从不提供比这更小的构建版本——一台无法运行 4-bit 构建、内存溢出到系统内存的机器，就是无法运行该模型。

无法承载的模型会保持可见并附上原因，因此你始终清楚一次硬件升级能释放哪些可能。

## 内存管理如何工作

本地模型成败取决于内存布局，因此 Hermes 端到端地管理它，且不暴露任何调节项：

- **模型以完全适配你 GPU 的上下文窗口启动**，并随着你的对话需要更多空间而朝其原生最大值增长。在长会话期间，你可能会在状态栏中看到 "Context window grown"——这是窗口在扩展，而非错误。
- **每个推荐模型至少获得 64K 上下文窗口。** 当模型大于你的 GPU 内存时，Hermes 会有意将溢出部分按影响最小的顺序（先放入专家权重，绝不放入注意力缓存）放到系统内存中，牺牲部分速度以保护上下文保证。
- **内存适配计算包含启动配置**，而不仅是模型文件：上下文状态、运行时缓冲区、视觉投影器和 MTP 缓冲区都要计入。对于多 token 预测（MTP），当更大的批次在相同上下文窗口下会溢出时，Hermes 会使用更小的批次。MTP 保持启用。当重启后恢复已增长的窗口时，也会进行相同的计算。
- **对话压缩之前会先做增长检查。** 如果更大的窗口无法适配、生成太慢，或已达到原生最大值，Hermes 会进行压缩，而不是声称一个服务器并未接收到的窗口。
- 空闲模型会在 15 分钟后卸载以释放 GPU 内存；它们会在下一条消息时自动重新加载。

## 状态栏

右键点击状态栏并启用 **System resources**，即可在本地模型运行时查看实时的 GPU 利用率、GPU 内存和 RAM。上下文仪表始终反映模型实际运行所用的窗口。

## 查找更多模型

目录是一个精心挑选的起点，而不是边界。同一页面上的 **Find more models** 部分会搜索整个 Hugging Face：

- 结果会显示下载次数以及针对你机器评估的逐文件适配检查，因此你在下载前就能知道某个构建版本是否能在你的 GPU 上完整运行。
- 你下载的任何模型，其行为都与目录模型完全一致——Hermes 会自己读取模型文件来决定上下文窗口和内存布局。唯一的区别是：社区模型不带有我们的 "validated"（已验证）测试徽章。
- 磁盘上已经有 `.gguf` 文件？**Add model file** 会将其链接到你的库中而不复制它（原文件仍留在原位置），并立即可用。

## 使用你自己的 llama-server

如果你的机器上已经运行着 llama-server，Hermes 会检测到它并使用它，而不启动自己的服务器。将自定义端点指向任何 OpenAI 兼容的服务器以获得完全手动控制——托管运行时只是默认选项，而非强制要求。对于手动配置（Ollama、MLX、自定义构建、无头 CLI 机器），请参阅
[使用 Ollama 本地运行 Hermes](/guides/local-ollama-setup) 和
[在 Mac 上运行本地 LLM](/guides/local-llm-on-mac)。

## 配置

托管运行时由 `config.yaml` 的 `local_runtime` 部分控制。桌面 UI 会为你写入这些值；这里列出它们是为了 CLI 和无头使用：

```yaml
local_runtime:
  enabled: false     # true = 随 Hermes 一起启动托管服务器。
                     # 桌面端的 "Use" 按钮会自动设置此项。
  backend: auto      # auto | cuda | metal | vulkan | hip | cpu
  tag: b10362        # 锁定 llama.cpp 版本；Hermes 会在重新验证后
                     # 随每个版本更新
```

模型和运行时构建位于 Hermes 主目录下（`models/` 和 `runtimes/llamacpp/`）。将本地模型选为主模型使用标准的 `model.provider: llamacpp` + `model.default` 设置——与其他每个服务商的形态相同。

## 要求与限制

- **Windows 和 Linux：** NVIDIA GPU（CUDA）或 CPU。**macOS：** Apple Silicon（Metal）。Vulkan 构建服务于 AMD GPU。
- 具有 8 GB+ 内存的 GPU 可舒适运行小型目录模型；16 GB+ 能以高质量运行 27–35B 模型。
- 模型下载在传输过程中会根据目录进行字节数校验；不完整的下载会被删除并上报，绝不会被半途使用。（只有运行时引擎的 zip 文件经过 SHA-256 验证。）
- 删除模型会移除它暂存的所有文件，包括视觉适配器和投机解码配套文件。
