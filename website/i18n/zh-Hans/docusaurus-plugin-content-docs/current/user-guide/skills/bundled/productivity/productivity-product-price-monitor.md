# 商品价格监控

监控某个具体的可购买商品，并在归一化后的到手总价或库存状况满足条件时告警。需明确处理规格变体、税费、费用、货币、库存、取消条款以及重复告警。设置在前台运行一次；周期性检查则作为 `cronjob` tick 运行（`price-watch` 自动化蓝图即为它搭建脚手架）。

## 何时使用

- “这台笔记本降到 1,000 美元以下时通知我。”
- “监控这些航班，票价低于 500 美元时提醒我。”
- “这家酒店有可退款的房间时告诉我。”
- “跟踪门票/房源的库存情况。”
- 针对已有价格监控的定时任务 tick 触发时（步骤 4-6）。

不适用场景：一次性的“现在多少钱”查询（直接使用 `web_search`/`web_extract`）。

## 流程 — 设置（前台，仅一次）

### 1. 定义确切的商品

记录来源 URL/服务商、可用的商品/房源 ID、规格变体、数量、地点、日期、出行人/入住人数、会员/登录假设、成色、卖家以及可接受的替代品。当两个变体不会被混淆时即完成。

### 2. 定义告警条件

指定货币、到手总价还是税前价、最高价格、库存/供货规则、运费、可退款性、舱位/房型/票档、冷却时间以及通知目的地。当合成示例都能得出确定性的告警判断时即完成。

### 3. 建立实时基线，然后安排定时任务

用 `web_extract` 或 `browser_navigate` 抓取一个有界的实时结果，记录获取时间、来源价格、费用/税费、库存状况以及条款。在前台抓取成功一次之前不要安排定时任务。将监控契约（商品、条件、基线观测）写入 `~/.hermes/price-watches/<watch-slug>.json` 下的状态文件，然后创建任务：

```
cronjob(action="create",
        schedule="every 6h",
        prompt="Load the product-price-monitor skill and run the tick for the watch contract at ~/.hermes/price-watches/<watch-slug>.json.",
        deliver=<user's destination>)
```

选择符合速率限制和网站条款的周期。当基线与确切的商品契约一致且任务已存在时即完成。

## 流程 — Tick（每次计划运行时）

### 4. 抓取并归一化

重新抓取来源。仅使用带时间戳的汇率进行货币换算，并保留来源货币。将基础价格、必付费用、运费/税费、总计以及库存状况分开。排除易变的页面元数据。抓取失败意味着状态未知：报告或跳过，但绝不能用错误页面覆盖上一个良好观测。当观测结果可与基线比较，或被明确标记为失败时即完成。

### 5. 比较并抑制重复

按需在达到阈值、符合条件的库存、实质性更低价格或价格回升时告警。将上一个良好观测和上一个告警指纹存储到状态文件中。重放同一个报价不得发送第二次告警；遵守冷却时间。当告警判断针对存储状态是确定性的时候即完成。

### 6. 发送告警或保持静默

当条件满足时，告警需包含：确切的商品/规格变体、观测到的到手总价与来源货币、库存/条款、阈值、抓取时间戳、来源链接以及重要的不确定性。切勿声称库存已预留。当没有符合条件的情况时，保持静默——除非要求了周期性的平安确认，否则不发送“仍在监控”的噪音。当状态文件反映本次运行时即完成。

## 常见陷阱

- 将基础票价与到手总价阈值进行比较。
- 在错误的尺码、卖家、舱位、日期或房型条款上告警。
- 用错误页面覆盖上一个已知良好值。
- 轮询过于频繁，触发封禁或违反网站条款。
- 在一次前台抓取成功之前就安排定时任务。

## 验证

- [ ] 监控契约固定了商品，使两个变体不会被混淆。
- [ ] 在创建任何任务之前，已有一次前台抓取成功。
- [ ] 告警判断可从状态文件确定性重放；重复项已抑制。
- [ ] 抓取失败从未替换已知良好状态。
- [ ] 告警携带到手总价、来源货币、时间戳以及来源链接。
