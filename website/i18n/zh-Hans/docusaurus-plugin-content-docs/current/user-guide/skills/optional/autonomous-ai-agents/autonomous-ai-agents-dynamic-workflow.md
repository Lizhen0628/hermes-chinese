# 动态工作流技能

将大型扇出工作作为工作流运行：计划、循环以及每一个中间结果都存放在脚本中和磁盘上，因此父级上下文只保留已验证的结果。涵盖一次性扇出、对抗式收敛（尝试 + 反驳者），以及集成数十个工作分支的多波次行动。它不会让 `delegate_task` 在重启后持久存在；那是看板集群（kanban swarm）的职责。

## 何时使用

当工作单元是明确的（一个文件、一个端点、一条记录），且单元数量超出单个上下文所能承载时，使用它。少于约 10 个单元或串行链式工作时跳过。针对 hermes-agent 本身的重构或修复行动，同时加载 `hermes-agent`（开发工作流）；本技能负责扇出形态。

## 前提条件

- `delegate_task` 可用，且 `delegation.max_concurrent_children` 已按波次规模设置
  （默认 10；运行时对大于该值的 `tasks=[]` 会给出清晰错误而非排队）。仅当
  子级必须自行扇出时才需要 `delegation.max_spawn_depth >= 2`。
- 一个从终端环境临时目录（`$TMPDIR`，否则平台临时目录）解析出的可写运行目录。
  绝不使用字面量 `/tmp`：Termux 没有 `/tmp`，原生 Windows 会在其上报错。使用
  `<tmp>/wf_<name>_<uuid>/`，每次运行唯一，这样被中断的先前运行不会留下陈旧输出被误读。
- `execute_code` 用于确定性层（其内部仅存在 `web_search`、`web_extract`、
  `read_file`、`write_file`、`search_files`、`terminal`、`patch`）。

## 如何运行

两层，由真实的能力边界划分：

| | A 层 — `execute_code` 脚本 | B 层 — `delegate_task` 批次 |
|---|---|---|
| 用于 | 确定性工作：抓取 N 个 URL、解析 N 个文件、运行 N 条命令、模板化 N 个输出、构建清单、合并输出 | LLM 判断工作：分类、审查、决定、撰写、反驳、重构单个单元 |
| 持有 | 循环、分支、中间变量 | 无；一次调用传入 `tasks=[...]`，每个任务拥有各自的隔离子智能体 |
| 工具 | 上述沙箱集合；它不能调用 `delegate_task` | 父级工具集，原样继承（无逐任务收窄）；子级失去 `delegate_task`、`clarify`、`memory`、`send_message`、`cronjob_manage` |
| 并发 | 由你控制（`ThreadPoolExecutor`、批次） | 受 `delegation.max_concurrent_children` 限制 |
| 成本 | 仅工具调用 | 每个任务一棵完整智能体树；线性倍增 |

先在 A 层完成确定性部分，仅在 B 层扇出不可约简的 LLM 步骤，在父级上综合。

### 后台优先：结果以消息形式重新进入

顶层 `delegate_task` 立即返回，每个任务一个句柄；每个子级的结果在其完成时作为新消息重新进入对话。你无法在调用后的一行读取 `out_*.csv`。完成所有不依赖子级的工作，给出单行状态，然后结束你的回合；每个结果消息到达时再处理。普通的后续用户消息不会取消子级；`/stop`、`/new` 和进程退出会。只有由编排器子智能体发出的委派（深度 > 0）是同步的。

## 快速参考

- 单元必须能在没有同级输出的情况下作答，否则它属于串行。
- 清单：每行一个单元，写入 `<run>/manifest.jsonl`；打印数量 + 运行目录。
- 每个子级：约 8-12 处机械编辑，或约 2-3k 行阅读，或约 50-70 KB 语料；
  按最大的单元确定规模。结构化输出写入文件，绝不用 `summary` 字段
  （它会在负载下截断）；使用分隔符分隔的行而非 JSON。
- 父级在合并前验证文件数量及每次运行的时效性。
- “停滞”的子级通常已完成其写入；先检查文件系统。
- 先做限定切片（一个目录、20 条记录），报告 token 成本，再扩大规模。

## 流程

### 一次性扇出

1. 分解为独立单元。
2. A 层预处理写入清单。
3. 对照上述限制确定分块规模；当任务数多于
   `max_concurrent_children`，自行发出有界波次。
4. B 层：一次 `delegate_task(tasks=[...])`；每个任务读取其切片，写入
   `<run>/out_<i>.csv`，打印状态词，停止。
5. 结束回合。随着结果消息到达，读取文件、验证、合并；跨切面的综合留在父级。

### 对抗式收敛（发现质量类工作）

1. 独立尝试：向 N 个子级（2-4 个）提出相同问题，每个 `context` 中使用不同的
   表述角度，每个将每条论断写一行到 `<run>/attempt_<i>.md`。仅限有定位、
   可单独证伪的论断（“`src/routes/users.ts:142` 中的 `POST /api/users/:id/role`
   没有角色检查”）；反驳者无法驳倒“auth 层有问题”。
2. 在父级上合并与去重；记录每条论断的同意计数。
3. 反驳者：第二批，被要求用反证驳倒每条论断，输出
   `claim_idx|survives|counter_evidence`。给他们来源，不给尝试的推理过程。
4. 仅呈现幸存者；以一行理由丢弃被反驳的论断。
5. 将第 2 轮的新论断再经过一轮反驳；当某一轮不再增加幸存者时停止，最多 3 轮。

同一机制可保护父级免受其自身错误前提的影响：当你交给子级一个启发式规则
（“立面（facade）上的每个补丁目标都是一条死缝”）时，告诉他们在据此行动
之前用证据反驳它。四个小队这样做，将 647 处的一揽子重写变成 59 个真实修复，
并节省了 130+ 个绿色测试。

### 行动形态（数十名工作者、若干波次、数小时）

一次性配方无法扩展到整库级别的遍历。真正有效的做法：

1. 先测量（LOC、热点、死符号、预言机语料库），写出 ONE个
   共享 `BRIEF.md` 以及每个集群的 `task_<cluster>.md`。每个子级都读这两者。
   当队伍漂移时（子级削减文档字符串而非删除代码），修补一次简报并引导；
   重新派发的子级会继承修复。
2. 独占所有权：每个工作者一个文件集群，在其之外的编辑在集成时被丢弃。
   单个文件内的子扇出占据行范围，并在其范围内定义助手，以便差异干净合并。
3. 每个已验证步骤在本地提交，不推送、不 PR、子级不 rebase。已提交状态是
   唯一的交接物；行动中死亡的每个工作者恰好丢失其未提交的尾巴。共享工作树
   索引的工作者仅用 `git commit -- <paths>` 提交；裸提交曾扫走过兄弟的已暂存块。
4. 队伍规模 12-16 并发。单次 OAuth 授权下超过约 40 个进程时，
   每小时的令牌刷新会奔涌成 401 并终结波次。其余排队。
5. 父级存活检查：报告 `completed` 但只有几十行日志，或分支上 0 次提交的
   子级尚未完成；查看其子分支，或使用前驱的工作树和差异重新派发它。
6. 每轮集成：冻结一个基准 SHA，机械地 rebase 干净分支，给每个冲突分支
   配一名自己的 rebase 工作者（“main 的行为胜出，在新结构中重新施加”），
   合并到一个集成分支，在合并树上运行完整测试套件。每个分支单独通过时的
   冲突仅在此处出现。下一轮从集成提交开始分支，使其工作者之间不会互相冲突。
7. 宣布一轮已集成之前：对每个分支，`git rev-list --count <integration>..<branch>`
   为 0。工作者在你合并其端点后仍在继续提交；曾以这种方式落下
   跨六个切片的 168 次提交。
8. 测试运行：机器上恰好一个运行器，位于锁文件之后，使用高 `-j`。许多并行的
   低 `-j` 运行器更慢且互相杀死对方的进程组。红色文件在同一 venv 中裸
   `origin/main` 工作树上重跑；相同的按文件失败集合是预先存在的，不是你的。
9. 结尾时前向移植，而非每轮做：冻结 main 的 SHA，将冲突文件按目录扇出给
   工作者，他们在无提交的单个合并工作树上编辑，随后父级一次性提交该合并。
   CI 从不在冲突的 PR 上运行，因此每次推送前重新合并 main。
10. 实时 QA 是它自己的波次：每个界面一个小组，隔离的 `HERMES_HOME`，
    在检查前写出预期，证据在磁盘上，仅报告，且只有 PR 与 main 的差异才算
    回归。绿色单元测试漏掉了那个 P0（一条已登录代码路径，没有测试覆盖它）。
11. 审查者论断得到与子级论断相同的对待：在“恢复”任何东西之前，对着基准做 A/B 对比。
   若干自信陈述的审查差异在基准上本就如此表现。
12. 父级重启需要一份 `HANDOFF.md`：它的死亡原因、哪些句柄已死、
    每个分支的记分卡（LOC 变化量、导入冒烟、定向测试），以及确切的重新派发文本。
    先将每个脏工作树快照到 `wip:` 提交中。

## 陷阱

- 在 `execute_code` 脚本内调用 `delegate_task`：不在沙箱中。
- 在与扇出调用同一回合综合：文件尚不存在。
- 承诺 `delegate_task` 后台可持久数天：它以回合为作用域，随进程死亡。
  持久图 = 看板集群；一次性 = `cronjob`。
- 依赖 `summary` 获取内容，或以 `status=completed` 判断完成。
- 每次“独立”尝试中同样的表述：它们坍缩为一个答案。
- 在工作树行动中的任何地方使用 `git stash`：`refs/stash` 跨工作树共享，
  另一名工作者会弹出你的编辑。通过临时工作树进行比较。
- 诚实的数字更低时却报告命中目标。说“目前 16%，以下是通往 30% 的路径”，
  并运行下一轮。

## 验证

- 清单行数与预期单元数量匹配。
- 每个 `out_*.csv` 都存在且是本次运行写入的。
- 每条被丢弃的论断都有记录的反证；每条呈现的论断都经过了反驳。
- 行动：每个分支 0 个未合并提交，在合并树上运行完整套件，对照裸 main 分诊的红色，
  每个界面一份实时 QA 报告，在完整运行之前报告限定切片的 token 成本。
