# 社交媒体内容日历

在选定的社交平台上规划一份具体的日历。此技能负责活动结构、帖子简报、渠道适配、审批和发布验证；`xurl` 等平台技能负责 API 命令。对于没有连接器的平台，经验证的交接终点是为用户的排程工具提供已批准的草稿——应如实说明，而非声称已发布。

## 何时使用

- “制定下个月的社交媒体日历。”
- “把这次发布转化为 X、LinkedIn、Instagram 和 TikTok 上的帖子。”
- “起草并排程一次活动。”
- “把这些文章/视频改编为社交内容。”

不适用场景：单次一次性帖子（直接使用平台技能）。

## 流程

### 1. 定义活动约束

记录目标、受众、卖点/信息、平台、日期范围、节奏、语气、必需/禁止的说法、链接、追踪约定、本地化，以及审批/发布权限。当每条拟定的帖子都有清晰的业务目的时即完成。

### 2. 盘点源材料

使用 `read_file` 和 `web_extract` 收集已验证的产品事实、发布信息、文章、媒体、获得许可的证言、品牌资产和关键日期。标注说法责任人和有效期。当不受支持的说法和缺失的资产清晰可见时即完成。

### 3. 构建主题和日历时段

创建均衡的内容组合，例如教育、实证、产品、社区、活动、幕后和对话。兼顾平台节奏和活动里程碑。当日期、平台、主题和目标组成一份连贯的日历，而非重复的跨平台转发时即完成。

### 4. 撰写平台专属简报

为每条帖子指定钩子、核心信息、格式、文案长度、CTA、链接、素材尺寸/内容、无障碍文本、标签/提及，以及成功指标。在不同平台间进行适配，而非复制粘贴。当创作者无需隐藏上下文即可产出素材时即完成。

### 5. 起草文案和素材

加载 `humanizer` 以确定语气；在需要素材时使用 `image_generate` 工具生成视觉内容。在尊重平台惯例的同时，保留事实性说法和统一的活动识别度。当每个日历时段都有草稿文案和素材状态时即完成。

### 6. 进行编辑与风险审查

检查事实准确性、语气、重复、权利/许可、无障碍性、披露信息、链接目的地、日期相关性，以及危机敏感度。标记为 `draft`（草稿）、`needs review`（待审查）或 `approved`（已批准）；不要从草稿状态发布。当每条帖子都有处理状态和负责人时即完成。

### 7. 排程或交接

提交审批批次。仅使用可用的平台技能（`xurl` 用于 X）发布/排程已批准的帖子；对于没有连接器的平台，将已批准的包（文案、素材、时间安排）交付给用户的排程工具，并将这些时段标记为已交接，而非已发布。对于任何实际发布的内容，回报排程时间、账号、内容预览，以及服务商帖子/任务 ID。当日历中每个时段都反映出已验证的发布或交接状态时即完成以。

## 常见陷阱

- 在每个平台上使用完全相同的文案。
- 用低价值的重复帖子填充节奏。
- 发布未经核实的指标、证言或未来说法。
- 将生成的素材完成误认为已排程发布。
- 对交接止于草稿的平台声称“已排程”。

## 验证

- [ ] 每条帖子都可追溯到活动目标和已验证的说法清单。
- [ ] 没有任何帖子从 `draft` 或 `needs review` 状态发布。
- [ ] 已发布的时段有服务商确认的 ID；已交接的时段有相应标记。
- [ ] 在任何发布之前检查权利、许可和披露信息。
