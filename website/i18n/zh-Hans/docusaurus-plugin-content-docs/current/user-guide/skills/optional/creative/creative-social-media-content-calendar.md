# 社交媒体内容日历

在选定的社交平台上规划一份具体的日历。此技能负责活动结构、帖子简报、渠道适配、审批和发布验证；而 `xurl` 等平台技能负责 API 命令。对于没有连接器的平台，经过验证的移交止于为用户调度器准备的已审批草稿——应如实说明，而非声称已发布。

## 何时使用

- "构建下个月的社交日历。"
- "把这次发布转化为 X、LinkedIn、Instagram 和 TikTok 的帖子。"
- "起草并安排一次活动。"
- "将这些文章/视频改编为社交内容。"

不适用于：单条一次性帖子（直接使用平台技能）。

## 流程

### 1. 定义活动约束

记录目标、受众、优惠/信息、平台、日期范围、发布节奏、语气、强制/禁止声明、链接、跟踪规范、本地化以及审批/发布权限。当每个拟议帖子都有明确的业务目的时，即为完成。

### 2. 盘点源材料

使用 `read_file` 和 `web_extract` 收集已验证的产品事实、发布信息、文章、媒体、经许可的推荐语、品牌资产和关键日期。标注声明负责人和有效期。当无依据的声明和缺失的资产可见时，即为完成。

### 3. 构建主题和日历槽位

创建均衡的组合，例如教育、证明、产品、社区、活动、幕后和对话。考虑平台节奏和活动里程碑。当日期、平台、主题和目标形成连贯的日历而非重复的交叉发布时，即为完成。

### 4. 撰写针对特定平台的简报

为每个帖子明确钩子、核心信息、形式、文案长度、行动号召（CTA）、链接、资产尺寸/内容、无障碍文本、标签/提及以及成功指标。要在平台之间进行改编，而非复制粘贴。当创作者无需隐藏上下文即可制作资产时，即为完成。

### 5. 起草文案和资产

加载 `humanizer` 以把握语气；在需要资产时使用 `image_generate` 工具生成视觉内容。在尊重平台规范的同时，保留事实性声明和共同的活动标识。当每个日历槽位都有草稿文案和资产状态时，即为完成。

### 6. 执行编辑和风险审查

检查事实准确性、语气、重复、权利/许可、无障碍、披露、链接目标、日期相关性和危机敏感性。标记为 `draft`、`needs review` 或 `approved`；不得从草稿状态发布。当每个帖子都有处置状态和负责人时，即为完成。

### 7. 安排或移交

呈现审批批次。仅使用可用的平台技能发布/安排已审批的帖子（X 平台使用 `xurl`）；对于没有连接器的平台，交付已审批的打包内容（文案、资产、时间安排）以供用户使用其调度工具，并将这些槽位标记为已移交，而非已发布。对于实际已发布的任何内容，需回读安排时间、账号、内容预览以及服务商帖子/任务 ID。当日历反映每个槽位经过验证的发布或移交状态时，即为完成。

## 陷阱

- 在所有平台上使用完全相同的文案。
- 用低价值的重复帖子填充发布节奏。
- 发布未经核实的指标、推荐语或未来声明。
- 将生成资产的完成与已安排的发布混为一谈。
- 对于移交止于草稿的平台，却声称"已安排"。

## 验证

- [ ] 每个帖子都可追溯到活动目标和经过验证的声明清单。
- [ ] 没有任何帖子是从 `draft` 或 `needs review` 状态发布的。
- [ ] 已发布的槽位具有服务商确认的 ID；已移交的槽位按此标记。
- [ ] 在发布前已检查权利、许可和披露。
